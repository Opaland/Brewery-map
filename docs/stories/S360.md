# S360 — Les références visuelles : seulement des images ordinaires *(issue #212, persona : le relecteur de workflows)*

## Objectif

Le relecteur de workflows sait que le job `commit` de
`.github/workflows/visuel-references.yml`, seul à tenir un jeton d'écriture,
ne committe que des fichiers ordinaires qui sont des PNG : un lien
symbolique, un dossier ou un autre contenu arrivé dans l'artefact arrête le
job avant le `git add`.

## Pourquoi maintenant

Revue globale du 22/10 (issue #212). L'artefact vient du code de la
branche ; le job `commit` l'ajoute par `git add '…/*.png'`, qui ne regarde
que le nom. `actions/upload-artifact` suit les liens au lieu de les garder,
ce qui rend le cas du lien improbable, mais rien dans le dépôt ne le dit
ni ne le vérifie : la garde doit vivre là où l'action se produit (§6quater).

## Critères d'acceptation

| # | Étant donné… quand… alors… | Prouvé par |
|---|---|---|
| CA1 | Un lien symbolique dans le dossier des captures reçues : l'étape de contrôle échoue, et le `git add` ne vient qu'après elle. | `tests/unit/workflows.test.ts`, « S360 » : le script de l'étape, lu dans le workflow, exécuté par bash sur un dossier de test (vu rouge : sans le contrôle, le script réussit) |
| CA2 | Un fichier `.png` dont les huit premiers octets ne sont pas la signature PNG, ou un fichier d'une autre extension : l'étape échoue. | même test |
| CA3 | Des PNG ordinaires : l'étape réussit. | même test |

## Hors périmètre

- Le contenu des images (une image valide peut être fausse) : la PR qui les
  reçoit se relit dans son diff, comme avant.
- Les autres workflows.
- **Ce que la garde ne fait pas** (relecteur de workflows) : un `push`
  exécute le workflow de la branche poussée ; un compte qui a l'accès en
  écriture peut retirer l'étape dans sa branche. La garde vaut contre un
  artefact piégé produit par du code de branche, pas contre ce compte (qui
  a déjà le droit de pousser). Un push depuis un fork ne lance pas ce
  workflow. Une vraie barrière demanderait un workflow lu depuis `main`
  (`workflow_run`) : au BACKLOG.

## Porte qualité

Verdict du 27/10 : **PASSE**, avec une limite dite (hors périmètre).

1. CA1 à CA3 : rouges sans l'étape (le script extrait réussissait), verts avec. Le lien symbolique, le faux PNG, le `.txt` (au contenu PNG, refusé par `find` seul) et le sous-dossier sont refusés ; des PNG ordinaires passent.
2. Revue adverse : le dossier lui-même en lien symbolique échappait au `find` (git l'arrêtait ensuite). Il est refusé par une garde ajoutée et par son test, vu rouge sans elle. Cas vérifiés sans défaut : dossier absent ou vide, `.PNG`, noms avec espace ou tiret.
3. Relecteur de workflows : un test verrouille le job `commit`, qui n'exécute que la garde et le commit (aucun `npm`, `node` ni `tsx` près du jeton), vu rouge en ajoutant `npm ci`. La limite face à un compte en écriture est dite ci-dessus. Le plafond de taille et de nombre est au BACKLOG.
4. Lint, `tsc -b` et tests unitaires verts.
