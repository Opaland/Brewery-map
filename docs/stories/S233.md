# S233 — Le JavaScript de `public/` linté *(revue d'architecture, dettes)*

## Objectif

`public/sw.js` (le service worker, cœur du hors-ligne) et
`public/theme-precoce.js` passent au lint comme le reste du code.

## Pourquoi maintenant

Revue d'architecture du 17/10 : `eslint.config.js` ne vise que
`**/*.{ts,tsx}` ; le fichier le plus critique pour le hors-ligne échappait
au lint.

## Critères d'acceptation

| # | Étant donné… quand… alors… | Prouvé par |
|---|---|---|
| CA1 | `npm run lint` lit `public/*.js`, avec les globales du service worker pour `sw.js` et du navigateur pour l'autre | `eslint.config.js` ; vu rouge : une variable non déclarée ajoutée à `sw.js` fait échouer le lint |
| CA2 | Ce que le lint trouve est corrigé, sans changer le comportement | `tests/unit/sw.test.ts`, e2e hors ligne |

## Hors périmètre

La liste manuelle de `tsconfig.node.json` (l'autre moitié de la dette) :
elle demande de séparer les composants testés en node, chantier à part.
