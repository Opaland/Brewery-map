# S331 — Une règle écrite une fois *(epic E32 ; persona : Hugo)*

## Objectif

Hugo ne lit plus une phrase que le code peut démentir. La région nommée
hors ligne est celle que le découpage calcule. « D'où vient la fiche »
cite toutes les lectures, datées ou non. Un code postal de Corse donne un
seul département, quel que soit l'outil qui le lit.

## Pourquoi maintenant

Revue adverse du 21/10, CLAUDE.md §4ter (« deux listes qui disent la même
règle ont le même trou ») :
- **Le département d'un code postal est écrit cinq fois.** `communes.ts` et
  `osm-france.ts` tranchent la Corse par `cp < '20200'` ;
  `curation.ts` accepte 2A et 2B pour tout 20xxx (S322) ;
  `decouverte.ts` et `candidats.ts` font `slice(0, 2)`, ce qui donne « 20 »
  pour la Corse. Conséquence : un déménagement vers Bastia (20200) passerait
  avec `d: '2A'`.
- **La région est écrite en dur.** « hors d'Auvergne-Rhône-Alpes » figure
  dans `App.tsx` et dans `en.ts`, alors que `decoupage.ts` la dérive du
  département 69.
- **Une lecture non datée est omise.** Quand un même site porte une lecture
  datée et une autre qui ne l'est pas, la seconde disparaît de « D'où vient
  la fiche ». Mesuré sur 7 fiches de `data/`.

## Porte qualité

Verdict : **PASSE**. Tests vus rouges : `code-postal` (module absent), le
déménagement vers Bastia (accepté avant), l'accord de la région (vu
échouer avec « Bretagne » écrit à la place), la provenance (« la fiche »
manquait).

Revue adverse :
- une clé React pouvait se doubler. Elle devient `quoi-date`.
- Un code d'outre-mer donne maintenant « 974 », que le schéma des fiches
  refuse. Avant, il donnait « 97 », qui n'est aucun département, et le
  schéma l'acceptait sans bruit. Le refus est voulu, et un test le tient.

Persona (Hugo), démo sur 7 fiches réelles (Nomade, Le Brass'in…) : « la
fiche, les horaires le 18 octobre » prêtait la date à la fiche. Les
lectures datées viennent maintenant d'abord, et la non datée porte « (sans
date de lecture) ». Porte verte.
