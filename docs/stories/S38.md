# S38 — QR code et affichette par fiche *(epic E4, persona : une brasserie)*

## Objectif

Une brasserie imprime, depuis sa fiche, une affichette de comptoir : son
nom, ce que dit la fiche, et un QR code qui ouvre sa fiche dans Mousse de
Poche. Tout se fabrique dans le navigateur.

## Pourquoi maintenant

C'est le levier « les brasseries » de `docs/MARKETING.md` (mois 2) : une
fiche juste, que la brasserie a intérêt à montrer.

## Critères d'acceptation

| # | Critère | Prouvé par |
|---|---|---|
| CA1 | Le QR code encode exactement le lien de la fiche (`lienDeFiche`, adresse publiée), rien d'autre | `tests/unit/qr.test.ts` : le texte encodé ; décodage de l'image dans le test e2e (jsQR) |
| CA2 | « Imprimer une affichette » ouvre la page d'impression : nom, commune, catégorie telle qu'affichée (« À confirmer » compris, avec sa raison), QR, adresse de l'application ; rien d'autre de la page | `tests/e2e/affichette.spec.ts` (émulation `print`, ce qui est peint) |
| CA3 | Aucune requête réseau pour fabriquer le QR | même fichier |
| CA4 | Le QR reste lisible imprimé : au moins 3 cm, avec marge blanche (« quiet zone ») de 4 modules | `tests/unit/qr.test.ts` (marge) ; taille CSS vérifiée en e2e |

## Hors périmètre

Un QR par lot (toutes les brasseries d'un département) ; un PDF.

## Décisions de Cédric requises

Aucune pour le code. **À dire à Cédric** : l'affichette montre ce que dit la
fiche aujourd'hui, « À confirmer » compris ; une brasserie qui l'imprime le
montre à ses clients.
