# S282 — Le fuzz des entrées non sûres : sauvegarde importée, lien partagé, signalement *(epic E27, persona : Léa)*

## Objectif

Léa peut ouvrir n'importe quel fichier « de sauvegarde » ou n'importe quel
lien `#fiche=…` reçu d'un inconnu : l'application ne plante pas, ne garde
rien d'invalide, et ce qu'elle relit reste dans ses bornes.

## Pourquoi maintenant

- Repris d'ÉtapeForge (`test/serverFuzz.test.js`), inventaire du 18/10
  (`docs/DEPOTS-FRERES.md`).
- Trois portes d'entrée venues de l'extérieur, lues le 18/10 :
  `lireSauvegarde` (un fichier choisi par la personne, S37), `ficheDuLien`
  (le fragment d'un lien partagé, S27), et `lirePreferences` sous les deux
  (et sous IndexedDB, qu'une autre version a pu écrire, S238). Les tests
  existants les essaient sur des exemples écrits à la main ; aucun ne les
  essaie sur des entrées qu'on n'a pas imaginées.
- `lienSignalement` recopie des champs de fiche dans une URL : il doit
  rester une URL GitHub valide quoi que contienne la fiche.

## Critères d'acceptation

| # | Étant donné… quand… alors… | Prouvé par |
|---|---|---|
| CA1 | Pour des milliers de valeurs aléatoires (JSON quelconque, formes presque valides, chaînes étranges : vides, très longues, emoji, demi-paires UTF-16, `__proto__`), `lirePreferences` ne lève jamais, rend des préférences dans leurs bornes (rayon, catégories, favoris uniques non vides, visites datées, notes ≤ 500, pas de clé en trop), et relire ce qu'il a rendu, passé par JSON, donne la même chose | `tests/unit/fuzz.test.ts`, graine fixe et rejouable (vu rouge : une borne retirée) |
| CA2 | `lireSauvegarde` ne lève jamais, sur texte quelconque ou JSON presque valide ; un « oui » rend des préférences qui tiennent CA1 et au plus 5 000 éléments par liste | idem |
| CA3 | `ficheDuLien` ne lève jamais ; pour tout nom bien formé, `ficheDuLien` relit exactement le nom que `lienDeFiche` a écrit | idem |
| CA4 | `lienSignalement`, pour des champs de fiche quelconques, ne lève jamais et rend une URL `https://github.com/…/issues/new` dont le corps contient le nom | idem |

## Hors périmètre

- Une bibliothèque de tests par propriétés (`fast-check`) : une dépendance
  de plus pour un générateur de quelques lignes ; écartée.
- Le fuzz dans un navigateur (S286, le test singe).

## Porte qualité

Verdict : **PASSE**.
- Aucune faille trouvée dans le code. Deux choses vues en chemin, sans
  défaut : une note reçue mal formée (demi-paire UTF-16 d'un fichier
  forgé) est gardée telle quelle et s'affiche « � » — le code promet
  seulement de n'en pas créer en coupant, et c'est ce qui est testé ; une
  catégorie `-0` est acceptée comme `0` (`-0 === 0` partout).
- Une borne que rien ne testait : au-delà de 5 000 favoris, visites ou
  notes, une sauvegarde n'est pas reprise (cas ajouté, vu rouge).
- Vu rouge par mutation : favoris non dédoublonnés, notes non coupées,
  coupe sans garde d'emoji, `ficheDuLien` sans `try`, borne des 5 000.
- Revue adverse : le fuzz était creux sur `depart`, `type`, `version`, les
  dates du calendrier (`2026-02-30` passait la regex), l'unicité des notes
  et les fragments mal encodés. Le générateur produit désormais de vrais
  départs (dont « autour » avec une position glissée, qui ne doit jamais
  être gardée, §0) et de vrais types ; `enDefaut` les lit indépendamment
  du schéma relu. Les six mutations qui survivaient sont rouges, et deux
  bornes de commune, testées une à la fois. Entrées réalistes sondées sans
  défaut : `__proto__`, nombres immenses, BOM (retiré par `File.text()`),
  100 000 niveaux d'imbrication.
