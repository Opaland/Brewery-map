# S310 — Ce que le premier écran attend : la couche OSM et la suite, mesurées avant d'y toucher *(epic : le premier écran quand le fichier grandit ; personas : Bernard, Hugo)*

## Objectif

Bernard, en 4G lente, voit la première ligne de la liste sans attendre ce
qui ne la change pas — si la mesure montre qu'il attend, sinon on le dit et
on n'y touche pas.

## Pourquoi maintenant

- BACKLOG, « S294 — restes » :
  - la couche OSM (878 brasseries) est un morceau à part (`osmFrance.ts`,
    `import()` dynamique), mais `main.tsx` **attend** son arrivée, jusqu'à
    3 s, avant le premier rendu ;
  - la suite des fiches (S294) n'est demandée qu'**après** le premier rendu ;
    un lien vers une fiche bretonne attend donc le stockage, la couche, puis
    la suite, en série.
- Ce que le code dit de l'attente de la couche (`main.tsx`) : arrivée
  après l'écran, elle faisait bouger la liste sous le doigt (S25) — les
  brasseries OSM voisines du départ s'intercalent en tête de liste. Ne plus
  l'attendre n'est donc pas gratuit.
- La revue adverse S294 l'a écrit : « à mesurer avant d'y toucher ».
- Référence, `docs/PREMIER-ECRAN.md` (S294, 20/10, PC fixe,
  `outils/mesure-premier-ecran.ts`, 5 essais) : LCP 1 808 ms, première
  ligne 1 840 ms.

## Le choix

Une story de **mesure d'abord**, comme S43. Trois variantes, même outil,
même poste, même construction des données :

| Variante | Ce qui change |
|---|---|
| A — `main` | rien (référence) |
| B — sans attente | le premier rendu n'attend plus la couche OSM (sonde jetable, non livrée : la liste bougerait) |
| C — demandés tôt | `index.html` annonce le morceau OSM et la suite (`<link rel="modulepreload">`), le même pour tout le monde : ils partent avec le paquet principal au lieu d'après son exécution |

B dit ce que coûte l'attente ; C est la seule candidate livrable dans
cette story (elle ne change ni ce qui s'affiche, ni l'ordre des rendus).

**Règle de décision** (seuil de présentation, CLAUDE.md §2, tranché ici) :
C est livrée si sa médiane de première ligne **et** sa médiane de LCP
gagnent sur A plus que l'écart entre essais de A (max − min, mesuré dans la
même série). Sinon : rien n'est livré, la mesure est écrite. Écarté :
un seuil fixe en millisecondes — rien ne le fonde sur ce poste.

AR3 (`docs/ARCHITECTURE.md` §4) : C annonce les mêmes fichiers à tout le
monde, dans le HTML statique ; rien ne dépend de la position.
