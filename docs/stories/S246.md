# S246 — L'outil « département » *(epic E25, persona : Cédric)*

## Objectif

Pour un département, Cédric reçoit une liste de candidats sûre : chaque
brasserie connue du registre SIRENE ou d'OpenStreetMap y figure une seule
fois. Celles déjà dans le fichier en sont écartées. Le nom d'une personne n'y
est jamais pris pour celui d'une brasserie. Ces candidats sont prêts à être
lus par les agents. Les lectures des agents s'assemblent ensuite en un lot de
fiches nouvelles, que Cédric décide ligne par ligne.

## Pourquoi maintenant

S244 (`docs/SIRENE.md`, 17/10) recommande de chercher dans SIRENE d'abord,
puis dans OSM. Dans la Manche :
- SIRENE donne 22 établissements et OSM 8 brasseries ; 5 sont dans les deux ;
- plusieurs établissements SIRENE n'ont pour nom que celui de l'entrepreneur ;
- l'API coupe souvent depuis le conteneur.

Il faut donc un outil qui fusionne les deux sources, retire les doublons,
protège les noms de personnes et reprend là où il s'est arrêté, avant le
pilote S247 (Manche et Calvados).

## Conception

- **`src/core/candidats.ts`** (TDD, §6) :
  - `candidatsDuDepartement(sirene, osm, fiches)` fusionne les
    établissements SIRENE et les points OSM d'un département en candidats :
    une brasserie, ses sources (SIRENE, OSM ou les deux), son adresse
    déclarée, sa commune ;
  - le classement reprend `classerCandidats` de S14 : présent, homonyme,
    doublon, ambigu, nouveau ;
  - `assemblerLot(candidats, lectures)` transforme les lectures des agents
    en `ajouts` validés par `ajoutSchema` (S14) ; une lecture invalide est
    rendue avec sa raison, jamais corrigée en silence.
- **`outils/departement.ts`** :
  - `candidats <dep>` interroge SIRENE (code 11.05Z, établissements
    actifs) avec reprise : chaque page lue est gardée dans
    `outils/cache/`, et une relance ne la redemande pas ;
  - il lit la couche OSM du dépôt et écrit
    `curation/dep-<dep>-candidats.{json,md}` ;
  - `assembler <dep>` construit `curation/dep-<dep>.json`, un lot au
    format de `outils/curation.ts`, que `controler` et `appliquer` savent
    déjà traiter.
- La lecture des sites et d'Untappd, le géocodage à l'adresse et les bières
  sont faits par les agents `verificateur-de-brasserie`, via le skill
  `lot-de-curation`. L'outil leur prépare les paquets et rassemble ce
  qu'ils rendent.
