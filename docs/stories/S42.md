# S42 — Les communes de France, hors ligne d'avance *(epic E5, persona : Bernard)*

## Objectif

Bernard installe l'application chez lui, puis, à la campagne et sans
réseau, tape une commune de départ : elle est trouvée, même s'il n'avait
jamais cherché de commune avant.

## Pourquoi maintenant

Revue globale S22 (BACKLOG) : la recherche de commune ne marche hors ligne
qu'après une première recherche en ligne. Le pied de page le dit, ce qui
avoue le défaut.

## Mesure

`public/communes-france.json` fait 1,2 Mo, soit 469 ko compressé (gzip,
mesuré le 17/10). L'ensemble des fichiers par département fait 389 ko
compressé.

## Critères d'acceptation

| # | Critère | Prouvé par |
|---|---|---|
| CA1 | Le service worker garde d'avance `communes-france.json` et `communes/departements.json` (précache complet, tout ou rien comme le reste) | `tests/unit/sw.test.ts` ou build : la liste du précache |
| CA2 | Hors ligne, sans recherche préalable, taper « lyon » propose Lyon (69) | `tests/e2e/hors-ligne.spec.ts` (vu rouge avant) |
| CA3 | Hors ligne, si le fichier d'un département manque, la recherche se replie sur le fichier entier | même test |
| CA4 | Le pied de page ne dit plus « demande le réseau la première fois » | même test ; `grep` sur toutes les surfaces (§3) |

## Coût, dit

Chaque installation télécharge environ 470 ko de plus, une fois. C'est un
choix de présentation et d'usage (§2) : une commune introuvable hors ligne
est le pire moment pour Bernard. L'autre piste, un bouton « garder les
communes », est écartée : elle demande de penser à le toucher avant de
partir.
