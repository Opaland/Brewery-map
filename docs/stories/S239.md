# S239 — Mutation outillée sur `src/core` *(revue d'architecture ; remplace S129)*

## Objectif

Trouver les tests creux sans y penser : un outil modifie le code du cœur
(un `<` en `<=`, une condition retirée) et compte les modifications
qu'aucun test ne remarque (CLAUDE.md §6bis).

## Pourquoi maintenant

Jusqu'ici, la mutation est faite à la main, test par test (« vu rouge »).
La revue d'architecture du 17/10 demande de l'outiller, en job de nuit,
hors de la porte (trop long pour elle).

## Conception

- Stryker (`@stryker-mutator/core`, lanceur Vitest), sur `src/core/**/*.ts`.
- Un job planifié chaque nuit, et à la demande ; **informatif** : il publie
  son rapport (survivants listés), il ne bloque rien.
- Pas de score minimal tant qu'une première mesure n'existe pas (§2).

## Critères d'acceptation

| # | Étant donné… quand… alors… | Prouvé par |
|---|---|---|
| CA1 | Stryker tourne sur le cœur avec la configuration du dépôt | lancé en local sur un fichier (`src/core/untappd.ts`), score relevé |
| CA2 | Un job de nuit le lance sur tout `src/core` et garde le rapport | `.github/workflows/mutation.yml` |
| CA3 | La première mesure complète est écrite, avec les survivants à traiter | `docs/MUTATION.md` (après la première nuit) |
