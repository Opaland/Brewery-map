# S377 — Le jeton hors du dépôt pendant que le code de la branche tourne *(issue #251, persona : le relecteur de workflows)*

## Objectif

Aucun job qui exécute le code d'une branche ne garde le jeton GitHub dans `.git/config`.

## Pourquoi maintenant

Revue globale du 30/10 (relecteur-de-workflows). Risque faible, le jeton étant en lecture seule, mais le job `captures` montre déjà le bon réglage.

## Critères d'acceptation

| # | Étant donné… quand… alors… | Prouvé par |
|---|---|---|
| CA1 | Chaque `actions/checkout` pose `persist-credentials: false`, sauf le job `commit` de `visuel-references.yml`, qui pousse | `tests/unit/ci.test.ts` (vu rouge avant le changement) |
| CA2 | La porte et le déploiement tournent toujours : aucune étape ne fait de `git fetch` ni de `git push` après le checkout | CI verte ; `grep` |

## Choix tranché

Stryker reste installé par `npm install --no-save`, à versions fixées : `docs/MUTATION.md` dit pourquoi il n'est pas dans `package.json`, le workflow est manuel et sans secret. Écarté : l'ajouter aux dépendances, qui ferait revenir le conflit écrit dans cette doc.
