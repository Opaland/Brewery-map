# S241 — Sonde publiée étendue *(revue d'architecture ; remplace S213 et S68)*

## Objectif

Prouver, sur la page que GitHub Pages sert vraiment, ce que la personne
fait : ouvrir une fiche, revenir hors ligne, être protégée par la même
politique de sécurité que celle qu'on teste en local.

## Pourquoi maintenant

La sonde actuelle (`page-deployee.spec.ts`) vérifie quatre choses :
- la page répond 200 ;
- le titre est affiché ;
- aucun asset ne manque ;
- aucune erreur JavaScript.

Elle ne dit rien du parcours, du hors-ligne publié (service worker et cache
servis par Pages) ni de la CSP publiée (`docs/REVUE-ARCHITECTURE.md`, tableau
des tests). Un déploiement vert sans elle ne prouve rien (CLAUDE.md §7).

## Critères d'acceptation

| # | Étant donné… quand… alors… | Prouvé par |
|---|---|---|
| CA1 | Sur la page publiée, une brasserie s'ouvre : sa fiche montre son nom, sa source et « Y aller » | `page-deployee.spec.ts` |
| CA2 | Sur la page publiée, le service worker précache toute la liste de `sw.js` publié, dans le cache de cette version | `page-deployee.spec.ts`, avec la même lecture du cache que `hors-ligne.spec.ts` (une fonction partagée, §4) |
| CA3 | La CSP de la page publiée est exactement `POLITIQUE` de `build/csp.ts` | `page-deployee.spec.ts` |
| CA4 | Chaque nouveau test est vu rouge en local sur une page servie qui le contredit | sortie de test, CLAUDE.md §1 |
| CA5 | La sonde reste verte sur la vraie page après le merge | job `page-publiee` |

## Ce que la story ne fait pas

Pas de mesure Lighthouse publiée (S235 couvre le poids). Pas de test hors
ligne « réseau coupé » : `setOffline` ne touche pas le service worker
(§1). On interroge le cache lui-même.
