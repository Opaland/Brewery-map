# S276 — Sans JavaScript : le bloc `<noscript>` gardé par un test *(epic E27, persona : Inès)*

## Objectif

Inès, dont le navigateur bloque JavaScript, ouvre la page et lit ce
qu'est Mousse de Poche, pourquoi la carte ne s'affiche pas et quoi faire,
plutôt qu'une page blanche ; et ce texte ne peut plus disparaître sans
qu'un test le voie.

## Pourquoi maintenant

- Repris de Sentiers (`tests/e2e/sans-js.spec.ts`), inventaire du 18/10
  (`docs/DEPOTS-FRERES.md`).
- Lu le 18/10 : `index.html` porte un bloc `<noscript>` (titre, ce que fait
  l'application, « activez JavaScript », message sanitaire) ; aucun test ne
  l'ouvre sans JavaScript (`grep -rn "javaScriptEnabled" tests` : rien).
  §3 rappelle que ce bloc est une surface de texte qu'on oublie.

## Critères d'acceptation

| # | Étant donné… quand… alors… | Prouvé par |
|---|---|---|
| CA1 | Page construite ouverte sans JavaScript : le titre, la phrase « activez JavaScript » et le message sanitaire sont **peints** (`elementFromPoint`), en thème clair comme en sombre | `tests/e2e/sans-js.spec.ts` (vu rouge : le bloc retiré de `index.html`) |
| CA2 | Sans JavaScript, la page ne demande rien hors de ce site | idem, requêtes relevées |
| CA3 | axe ne relève aucune violation WCAG A/AA sur la page sans JavaScript (contraste compris), en clair comme en sombre | idem, `@axe-core/playwright` comme `accessibilite.spec.ts` (vu rouge : couleur de texte forcée) |

## Hors périmètre

  l'architecture (`docs/ARCHITECTURE.md`, page statique).
